# T08 — `aw review` workflow

Depends on: T04, T05, T07. Read first: `tasks/SPEC.md` (Review output contract, Agent session loop, exit codes).
Goal: headless-safe branch review with parsed, severity-sorted findings.

## Steps

1. Create `src/workflows/review.ts` exporting `runReview(opts: { base: string; provider?: string; model?: string; config?: string; workspace?: string }): Promise<{ verdict: Verdict; findings: Finding[]; raw: string }>`:
   1. `cfg = loadConfig(opts)`; `{ provider, model } = resolveModel('code-reviewer', opts, cfg)`.
      If provider is `claude-cli`, exit 1 with the SPEC-mandated message (use `anthropic`
      or `.claude/` native path).
   2. In `cfg.repoRoot`: `git rev-parse --verify <base>` (error → readable message, exit 1);
      `diff = git diff <base>...HEAD`; empty diff → print `nothing to review` exit 0.
      Also collect `git diff --name-only <base>...HEAD`.
   3. Build the user prompt: the diff (cap 60 KB; if larger, include per-file diffs up to the
      cap and list the omitted files) + instruction: *"Review this diff. Use read_file/grep
      to read surrounding context of changed files before judging. Then output in the exact
      VERDICT format."*
   4. `generateText({ model: getModel(provider, model), system: agent.system, prompt, tools: makeCoreTools('reviewer', cfg.repoRoot), stopWhen: stepCountIs(25) })`.
   5. Parse `r.text` with the SPEC regexes into `verdict` + `Finding[]` (sort BLOCKER→NIT).
      If the VERDICT line is missing, retry ONCE appending *"Your previous output violated
      the format. Output only the required format."*; still missing → exit 1 printing raw text.
   6. Print to stdout: the verdict line, then each finding in the contract format. Plain
      text only, never prompt for input.
   7. Return value + exit code `2` if any BLOCKER, else 0.
2. Create `src/commands/review.ts` with `registerReview(program)`: options
   `--base <b>` (default `main`), `--provider`, `--model`, `--config`, `--workspace`;
   calls `runReview`. Register in `src/cli.ts`.

## Acceptance

Run inside any local git repo that has an `aw.config.json` (create a throwaway repo if
needed — e.g. copy `aw.config.example.json`, adjust `repoRoot`, commit a base, then branch
and introduce an obvious bug such as an unvalidated SQL string concat):

```
npx tsx <this-repo>/src/cli.ts review --base main --config ./aw.config.json
```
1. Output starts with `VERDICT:` and the planted bug appears as a finding with file:line.
2. Repeat with a second `--provider` (e.g. lmstudio AND anthropic) — both produce the format;
   at least one flags the planted bug as BLOCKER/MAJOR (small local models may rate lower).
3. `echo $?` is `2` when a BLOCKER was reported.

## Out of scope
No manifest writing (T16). No PR/network operations.
