# T22 — Trigger workflows + live logs from the dashboard

Depends on: T18–T21. Read first: `tasks/SPEC.md` (CLI commands, Storage).
Goal: start, watch, and cancel runs without leaving the panel.

## Steps

1. `dashboard/src/lib/runner.ts` (server-only, module-level state):
   - `startRun(ws, kind, args: Record<string,string>)`: build the argv for
     `npx tsx <repoRootOfThisToolkit>/src/cli.ts <kind> …` (toolkit root = resolve from
     `process.cwd()/..`), spawn with `cwd` = workspace repoRoot, env passthrough;
     pipe stdout+stderr to `<awHome>/<ws>/pending/<pid>.log` until the CLI prints
     `run saved: <ws>/<runId>` — then move/append the log into that run's `log.txt`.
     Track `{ pid, ws, runId?, startedAt }` in a module map AND `<awHome>/<ws>/pending/pids.json`.
   - `cancelRun(pid)`: `process.kill(pid, 'SIGTERM')`; after 10 s escalate SIGKILL; the CLI's
     finally-block (T16) marks the manifest `cancelled` — add a SIGTERM handler in
     `src/cli.ts` that sets `status: 'cancelled'` before exit.
2. API:
   - `POST /api/trigger { ws, kind, args }` → `{ pid }`. Validate kind ∈ 3 workflows; args
     whitelist per kind (review: base/provider/model; test-feature: desc/url/allowDestructive/…;
     design-loop: feature/iterate/…). Reject anything else (no shell injection surface —
     always spawn with an argv ARRAY, never a shell string).
   - `GET /api/logs?ws=&pid=|run=` → SSE (`text/event-stream`): send existing content, then
     `fs.watch`-based tail; heartbeat every 15 s; close on client disconnect.
   - `POST /api/cancel { pid }`.
3. UI:
   - "New run" button on workspace page → modal: kind select + the per-kind arg fields
     (feature textarea, base input, url input, provider/model overrides) → trigger → jump to
     a live view streaming the SSE log (auto-scroll with pause-on-manual-scroll), Cancel
     button, and on completion a link to the finished run page.
   - T20's queued feedback gets an "Apply now" button: triggers
     `design-loop --iterate "<queued text>"` and removes it from the queue on success.
   - Running runs show a spinner badge in all run tables (poll `/api/runs` every 5 s or
     revalidate).
4. Concurrency guard: max 1 running workflow per workspace (409 with message otherwise).

## Acceptance

1. Trigger a review from the modal → live log streams tokens/tool calls → on finish the run
   appears with correct status and its Review tab renders.
2. Cancel mid-run → process exits, manifest `status: "cancelled"`, UI badge gray.
3. Apply a queued T20 feedback → an `--iterate` design-loop run starts and the queue entry
   disappears after success.
4. Second trigger on the same workspace while one runs → clear 409 message in the modal.
5. `args` containing `"; rm -rf ~"` executes nothing (argv array — verify the string arrives
   as a literal argument in the log).

## Out of scope
No auth (localhost-only tool), no multi-user, no queueing beyond the 1-per-workspace guard.
