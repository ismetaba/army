# T10 — `aw design-loop` workflow

Depends on: T08, T09 patterns; T06. Read first: `tasks/SPEC.md`; `agents/ui-designer.md`.
Goal: implement UI → verify in browser → screenshots → checkpoint commit → stop for feedback; iterate mode.

## Steps

1. Create `src/workflows/design-loop.ts` exporting
   `runDesignLoop(opts: { feature: string; iterate?: string; provider?: string; model?: string; config?: string; workspace?: string })`:
   1. Resolve config + model for `ui-designer` (same claude-cli refusal as T08).
   2. If `opts.feature` is a path to an existing file, read it as the spec text; otherwise
      treat it as the description. `slug = slugify(description first 6 words)`.
   3. Start the app: for `cfg.app.backend` and `cfg.app.frontend` (if configured and their
      port is not already listening — check with a fetch/`net` connect): spawn `start`
      command in `repoRoot`, poll port up to 60 s (reuse/extract the helper written in T09
      step 3 into `src/util.ts` as `ensureUp()`).
   4. PLAN step: one `generateText` WITHOUT tools, prompt = feature + list of files from
      `git ls-files` matching frontend dirs + *"Output a UI plan in at most 5 lines:
      screens, components, states."* Print the plan, do not wait.
   5. IMPLEMENT+VERIFY session: `generateText` with designer profile tools + browser tools
      (`screenshotDir = <repoRoot>/screenshots/<slug>`), `stopWhen: stepCountIs(60)`.
      Prompt = plan + feature + frontend base URL + *"Implement, then run your self-review
      checklist loop from your instructions on every touched screen at both viewports.
      Save final screenshots named <screen>-<viewport>. End with the required summary."*
      If `opts.iterate` is set, prepend: *"Apply this feedback to the existing
      implementation, re-verify ONLY the affected screens: <feedback>"*.
   6. After the session: verify at least one PNG exists under `screenshots/<slug>/`
      (else exit 1: `agent finished without screenshots — not acceptable`).
   7. Checkpoint commit in `repoRoot`: `git add -A && git commit -m "design-loop(<slug>): checkpoint"`
      (skip cleanly if nothing to commit). NEVER push.
   8. Print the presentation block: changed files (`git show --stat HEAD` names), screenshot
      paths, judgment calls (from agent summary), then exactly:
      `--- STOPPING FOR FEEDBACK — resume with: aw design-loop "<feature>" --iterate "<your feedback>" ---`
   9. `closeBrowser()` in a finally block; kill spawned dev-server processes we started.
2. `src/commands/design-loop.ts` → `registerDesignLoop(program)`: arg `<feature>`, options
   `--iterate <feedback>`, `--provider`, `--model`, `--config`, `--workspace`. Register in cli.ts.

## Acceptance

In a target repo with a runnable frontend (any small app):
```
npx tsx src/cli.ts design-loop "add a placeholder /about page with a heading" --config <target>/aw.config.json
```
1. Prints ≤5-line plan, implements, saves `screenshots/<slug>/*-mobile.png` and `*-desktop.png`,
   makes exactly one checkpoint commit, prints the STOPPING FOR FEEDBACK line, exits 0.
2. `... --iterate "make the heading bigger"` changes the code, re-screenshots only affected
   screens, commits another checkpoint, stops again.
3. `git log` shows NO push occurred (no remote tracking change).

## Deviations

1. **`ensureUp()` and `slugify()` were already in `src/util.ts`.** Step 1.3 asks for the T09
   helper to be extracted there; T09 had already done it, so both are imported unchanged and
   nothing was added to `util.ts`. The T09 stuck-agent stop condition `isLooping` is imported
   from `src/workflows/test-feature.ts` for the same reason, making `stopWhen`
   `[stepCountIs(60), isLooping]` rather than `stepCountIs(60)` alone.

2. **The PLAN step also receives the `--iterate` feedback.** Step 4 lists only the feature; on
   an iteration that would produce a plan for the original build, which then leads the session
   prompt. The feedback is passed as one extra line, and the ≤5-line output rule is unchanged.

3. **The session prompt carries operational rules beyond step 5's wording.** The step-5 sentence
   is sent verbatim, followed by: never start/restart/stop a server (the workflow already
   started it — a `npm run dev` issued through `bash` outlives the session and holds the port,
   observed in T09), never run `git add`/`git commit`/`git push` (the workflow makes the
   checkpoint, and an agent commit turns step 7 into "nothing to commit"), at least one
   screenshot per touched screen per viewport, check `browser_console_errors`, never ask
   questions. Without them, step 6's guard fails runs that were otherwise fine.

4. **`checkpoint()` decides "nothing to commit" *after* staging** — `git add -A`, then
   `git diff --cached --name-only`. Checking `git status` first would miss index-only changes
   and would also count ignored-but-untracked noise that the commit does not contain.

5. **A checkpoint that genuinely *fails* prints the presentation block and then exits 1**
   (step 7's "skip cleanly" covers only "nothing to commit", which exits 0 and says so on
   stderr). The screenshots and the code survive on disk either way, but the resume line would
   otherwise promise a checkpoint that does not exist.

6. **Step 6's guard stays "at least one PNG exists"; staleness is a warning.** Requiring a PNG
   newer than the session start would contradict step 5's "re-verify ONLY the affected screens"
   in `--iterate` mode, so a run whose PNGs all predate the session logs a warning instead of
   failing, and 0-byte PNGs are reported by name.

7. **`design-loop` refuses to run without a UI URL** — exit 1 when neither `app.frontend.port`
   nor `app.baseUrl` is configured, since every acceptance criterion depends on the agent
   opening the app in a browser.

8. **Observed in the live `--iterate` acceptance, left as a warning:** after implementing and
   re-verifying the affected screen, the 30B local model spent its remaining steps alternating
   between `glob {"pattern":"src/**/*.{ts,tsx,js,jsx}"}` and the same pattern with the extensions
   reordered, so `isLooping` (five *identical* consecutive calls) never fired and the session
   used all 60 steps. The run still produced the change, the screenshots and the checkpoint, and
   exits 0 with `warning: the agent used its whole 60-step budget without finishing`. Widening
   the loop detector belongs to `isLooping` in T09's file, which is out of this task's scope.
