# T14 — Wire to the real project + handoff acceptance checks

Depends on: T13 (and all before it). Read first: `docs/HANDOFF.md` § Acceptance check.
Goal: prove the whole toolkit end-to-end on the developer's chosen repo.

## Steps

1. ASK the developer which repo to wire (do not guess). Run `aw init` against it
   interactively with them (fill real start commands/ports/test account env).
2. If the target has no frontend yet: ask which framework they want, scaffold it inside the
   first design-loop run (HANDOFF Step 0 note), keeping it minimal.
3. Run the acceptance sequence from HANDOFF, in order, in the target repo on a fresh branch
   `aw-acceptance`:
   1. `npx tsx <this-repo>/src/cli.ts design-loop "add a simple placeholder page" --config ./aw.config.json`
      → must produce screenshots + summary, stop for feedback.
   2. Re-run with `--iterate "make the heading bigger"` → must revise, re-screenshot, re-present.
   3. `npx tsx <this-repo>/src/cli.ts test-feature "the health endpoint returns 200 with build info"`
      (or the closest real endpoint) → must produce a report file.
   4. Review: the documented headless command from T12 (native or fallback) on the branch →
      verdict + severity-sorted findings.
4. Show the developer the final tree of every file created/modified in BOTH repos
   (`git status --short` + `find .claude screenshots test-reports -type f` in the target).
5. Fix anything that failed and re-run only the failed step, until all four pass.

## Acceptance

All four HANDOFF checks pass on the real repo, evidenced by: screenshot paths (both
viewports), a second iteration commit, a `test-reports/*.md` file, and a review verdict —
all shown to the developer in one summary. Developer says it's approved.
