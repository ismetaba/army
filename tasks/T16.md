# T16 — Run manifest + workspace store (retrofit T08–T10)

Depends on: T10. Read first: `tasks/SPEC.md` (RunManifest, Storage).
Goal: every workflow run leaves a machine-readable trail the dashboard can render.

## Steps

1. Create `src/store.ts` exporting:
   - `awHome(): string` → `process.env.AW_HOME ?? ~/.agent-workflows` (expand `~` via `os.homedir()`).
   - `newRun(workspace: string, kind: RunManifest['kind']): { runId: string; dir: string }`
     — `runId = `${kind}-${timestamp}`` where timestamp is `YYYYMMDD-HHmmss` local time;
     creates `<awHome>/<workspace>/runs/<runId>/artifacts/`.
   - `writeManifest(dir: string, m: RunManifest): void` — validate with `RunManifest.parse`
     first, pretty-print JSON.
   - `appendLog(dir: string, line: string): void` → `log.txt` with `[HH:mm:ss] ` prefix.
   - `saveArtifact(dir: string, name: string, content: string | Buffer): string` → writes to
     `artifacts/<name>`, returns the RELATIVE path `artifacts/<name>`.
   - `listRuns(workspace?: string): RunManifest[]` (newest first), `readRun(workspace, runId)`.
2. Retrofit the three workflows (small, surgical edits):
   - Start: `const { runId, dir } = newRun(cfg.workspace, kind)`; write an initial manifest
     with `status: 'running'` and the `input` block.
   - Route the existing stderr tool-call logging ALSO through `appendLog`.
   - `review`: save the diff via `saveArtifact(dir, 'diff.patch', diff)`; on finish set
     `review: { verdict, findings, diffArtifact }`.
   - `test-feature`: copy the report file → `saveArtifact(dir, 'report.md', …)`; set
     `test: { reportArtifact, cases, summary }`.
   - `design-loop`: copy final screenshots into `artifacts/screenshots/` (keep originals in
     the target repo too); set `design: { screens (paths relative to run dir), judgmentCalls,
     feedbackHistory (append `--iterate` texts) }`.
   - Finish: `status: 'done' | 'error'`, `durationMs`, `error` message when thrown. Wrap each
     workflow body in try/catch/finally so a crashed run still ends with `status: 'error'`.
   - Print at the very end of every run: `run saved: <workspace>/<runId>`.
3. `src/store.test.ts`: newRun creates dirs; writeManifest rejects an invalid manifest;
   listRuns sorts newest first (create two with different timestamps by passing a clock
   param or monkeypatching Date).

## Deviations

1. **`awHome()` already existed in `src/util.ts`** (T03, step 2 of that task). `src/store.ts`
   re-exports it rather than defining a second copy, so `AW_HOME` has one implementation and
   `resolveConfigPath()` (which reads `$AW_HOME/workspaces.json`) cannot drift away from where
   the runs are written.

2. **`shared/schemas.ts` already carried `RunManifest`, `Workspace` and `WorkspacesFile`** — T03
   created the file from SPEC § Types in full. The only change made here is three TS type
   aliases (`ScreenShot`, `Workspace`, `WorkspacesFile`) next to the zod objects, because the
   dashboard imports the *types* and SPEC's block already exports one for every other schema.
   No schema shape was touched.

3. **`process.exit` is the real failure path, so a `try/catch` alone cannot keep the promise.**
   Every workflow error goes through `fail()`, which prints and calls `process.exit(1)`: nothing
   unwinds, so no `catch` and no `finally` ever runs. `startRun()` therefore installs a net —
   one `process.on('exit')` handler plus `SIGINT`/`SIGTERM`/`SIGHUP` handlers — that writes a
   terminal status for any run still open. `fail()` hands its message to `noteRunFailure()`
   first, so the recorded `error` is the sentence the user was shown, not a generic
   "the process exited". The step-2 `try/catch/finally` is still there and is what catches a
   genuine throw; the net is what catches the other 90 % of exits.

4. **Signals are `cancelled`, not `error`,** and the handler exits with the conventional
   128+signal code (SIGTERM → 143). Registering a handler replaces the default "die now"
   behaviour, so it must exit explicitly — that also lets the `exit` handlers in `ensureUp()`
   (src/util.ts) run, instead of leaving a dev server holding port 3001/5173.

5. **Each workflow was split, not indented.** `runReview` / `runTestFeature` / `runDesignLoop`
   keep their prelude (config, model resolution, target/base resolution) and hand the rest to
   `reviewSession()` / `testFeatureSession()` / `designSession()`, which the `try/catch/finally`
   wraps. Re-indenting 200–300 lines inside a `try` would have produced a diff in which the
   recording changes are invisible. The run starts at the first point where every required
   manifest field is known — a `--provider claude-cli` refusal or an unreadable config is not a
   run and leaves no manifest.

6. **The stderr logging is routed through a sink, not a threaded argument.** `log()` is called
   from ~80 places across the three workflows and none of them knows the run directory;
   `setLogSink(run.log)` in the wrapper is one line instead of 80. `write(1, …)` is mirrored
   too, so `log.txt` ends with the run's actual result (the VERDICT block, the report path)
   rather than with its last tool call.

7. **`review` prints its verdict with `write(1, …)` instead of `console.log`.** Same bytes on
   stdout; it is the call the sink mirrors, and it is synchronous, so the verdict cannot be lost
   in a pipe buffer when the process exits.

8. **`run saved: <workspace>/<runId>` goes to stderr.** stdout is the contract channel — SPEC §
   Review output contract is parsed by `claude -p` and by `aw review > out.txt`, and
   `test-feature` prints the report path there for scripts to read. A meta line on stdout would
   break both. It is printed from `finish()`, so a cancelled or crashed run announces itself the
   same way a successful one does.

9. **`artifacts/diff.patch` is the diff *as sent to the model*,** saved before the first model
   call and re-saved after each context-overflow shrink (T14's halving loop). The alternative —
   the complete `git diff` — would not be the diff the verdict is about, which is what the panel
   has to show next to the findings. When the 60 KB cap trimmed something, the artifact carries
   the `…[diff for X truncated]` markers inline.

10. **`design.feedbackHistory` is keyed on the feature argument.** A run started with
    `--iterate` reads the newest previous `design-loop` run whose `input.feature` matches and
    appends its own feedback, so run N carries all N−1 requests rather than only the latest.
    An `--iterate` run writes that history into its manifest *before* the session starts, so a
    run that dies still hands the chain to the next one instead of breaking it.
    Screenshots are **copied** into `artifacts/screenshots/` (originals stay in the target repo,
    per T10 step 6) because `--iterate` reuses the slug directory and overwrites them — without
    the copy, run N's manifest would point at run N+1's pixels and T20's run-over-run compare
    would show the same image twice. The viewport is read back off the
    `<screen>-<viewport>.png` name that `browser_screenshot` produces.

11. **Beyond the step-1 list, `src/store.ts` also exports** `startRun()` (the recorder above),
    `runsDir`/`runDir`/`workspacesPath`, `readLog()` and `listWorkspaces()` — the dashboard
    needs to locate a run's `log.txt` and artifacts and to name its workspaces, and all of that
    is `$AW_HOME` knowledge that belongs in exactly one module. `listRuns`/`readRun` take an
    optional `{ onWarn }` so a caller that is not a terminal can collect the skips instead of
    having them printed.

12. **Two collisions the naive implementation loses data to** are handled: a second run started
    in the same second gets `-2` (`mkdir` without `recursive`, so `EEXIST` is visible rather
    than silently shared), and `writeManifest` writes through a temp file + `rename`, so a
    dashboard polling the file never reads half a manifest.

13. **Recording never breaks the run it records.** A mid-run `update()` whose payload the schema
    refuses (or that a full disk stops) warns on stderr and in `log.txt` and carries the reason
    into the finished manifest's `error` — it does not throw, because that would turn a
    completed review into a crashed one. `finish()` applies the same rule to itself: if the
    `review`/`test`/`design` block does not validate, the manifest is still written with the
    terminal status, `durationMs` and an `error` naming what was rejected.

14. **`review` on an empty diff finishes the run as `done` before `process.exit(0)`.**
    "nothing to review" is a completed run, and without the explicit finish the exit net would
    have recorded it as an error.

15. **`workspace` must be a single safe path segment, which SPEC's `AwConfig.workspace`
    (`z.string()`) does not require.** It becomes a directory under `$AW_HOME`, so `checkSegment`
    rejects anything else and the run aborts with a message naming the rule (exit 1, no stack
    trace) rather than recording into a path the name implies. This is a real narrowing of what
    a hand-written `aw.config.json` may contain — `aw init` (T13) already enforces the same rule,
    so only hand-written configs are affected — and it is recorded here rather than fixed:
    slugifying the name for the directory while keeping the raw name in the manifest would make
    two different configs record into the same workspace. SPEC § Types is unchanged.

16. **The `error` for a store that cannot be written now names `$AW_HOME`.** `newRun` wraps its
    `mkdir` failures in `StoreError` (`cannot create the run directory … under $AW_HOME (…):
    EACCES — …`) instead of letting a bare errno string out; the setting the user has to change
    is the one thing the raw message never mentioned. The `EEXIST` of the id-collision loop is
    passed through untouched, because that one is handled, not reported.

17. **`RunHandle.artifact()` never throws.** It was the last recording call that could turn a
    finished run into `status: "error"` — deviation 13's rule with a hole in it: a full or
    read-only store made `run.artifact('report.md', …)` throw out of a test run that had already
    written its report and parsed every case. A failed write now warns on stderr and in
    `log.txt` and still returns the run-RELATIVE path it would have written, because manifest
    artifact paths are relative by contract (step 2) and the panel renders one whose file is
    absent as "file missing" rather than as a link. Consequently `design-loop`'s
    `copyScreenshot()` no longer falls back to the screenshot's ABSOLUTE path when the copy
    fails: it drops the entry from `design.screens` (the log still says where the original is),
    so every `screens[].path` is a run-relative `artifacts/…` path.

18. **A run started WITHOUT `--iterate` records an empty `feedbackHistory`.** Deviation 10's
    chain is read only on the `--iterate` path. A fresh first pass over a feature that was
    iterated on before — after a revert, say — was inheriting the older chain and recording
    feedback it had never been given, which T20's run-over-run compare would then attribute to
    it. The `--iterate` behaviour (run N carries all N−1 requests) is unchanged.

19. **The "a run never stays `running`" promise is scoped to exits the process can observe.**
    `SIGKILL` and power loss run no handler, so both do leave a ghost `running` manifest that
    nothing later rewrites. The header comment says so now instead of stating the invariant
    flatly; distinguishing a ghost from a live run is a reader's job (comparing the manifest's
    age against the clock) and no such check was added to the panel here.
