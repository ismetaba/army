# T17 — Dashboard skeleton

Depends on: T16. Read first: `tasks/SPEC.md` (Storage, port 4400).
Goal: Next.js panel listing workspaces and runs, with run-detail routing.

## Steps

1. From the repo root:
   ```
   npx create-next-app@latest dashboard --ts --app --tailwind --eslint --src-dir --import-alias "@/*" --use-npm
   ```
   Answer any extra prompts with the default. Then in `dashboard/package.json` set the dev
   script to `next dev -p 4400`.
2. Enable importing repo-root code: in `dashboard/next.config.ts` set
   `experimental: { externalDir: true }`; in `dashboard/tsconfig.json` add
   `"../shared/**/*"` to `include` and path alias `"@shared/*": ["../shared/*"]`.
   Verify `import { RunManifest } from '@shared/schemas'` compiles (schemas only — do NOT
   import from `src/`, it may pull node-only deps into client bundles; server routes only).
3. Data access `dashboard/src/lib/store.ts` (server-only): re-implement the READ side against
   the same layout — `awHome()`, `listWorkspaces()` (parse `workspaces.json`),
   `listRuns(ws?)`, `readRun(ws, id)`, `readArtifact(ws, id, relPath)` (resolve + REJECT
   paths escaping the run dir). Validate everything with the zod schemas.
4. Routes (server components, plain Tailwind, no extra UI libs):
   - `/` — workspace cards (name, repoRoot, run count) + latest 20 runs across workspaces.
   - `/ws/[ws]` — run table: runId, kind, agent, provider/model, status badge
     (running=blue, done=green, error=red, cancelled=gray), createdAt, duration; filter by
     kind via searchParam `?kind=`.
   - `/ws/[ws]/run/[id]` — generic run detail: manifest summary header + tabs placeholder
     (`Review | Report | Design | Log`); Log tab shows `log.txt` (monospace, tail last 500
     lines). Type-specific tabs are T18–T20 — render "coming soon" for now.
   - `/api/artifact?ws=&run=&path=` — streams an artifact file with correct content-type
     (png/webm/md/patch), 404 on traversal or missing.
5. Header nav: app name, workspace switcher (links), nothing fancy.

## Acceptance

```
cd dashboard && npm run dev
```
Open http://localhost:4400 — with ≥2 workspaces and ≥3 runs present (create with real runs
or hand-written valid manifests): home lists them; workspace page filters by kind; run page
shows header + Log tab content; `/api/artifact` serves a real `diff.patch` and 404s on
`path=../../etc/hosts`.

## Out of scope
No mutations, no triggering (T22), no type-specific views (T18–T20).

## Deviations

1. **`create-next-app` produced Next 16.3.2 / React 19.2 / Tailwind v4, not the webpack-era
   layout the step assumed.** Two consequences. `experimental.externalDir` alone is not enough:
   `next dev` runs Turbopack, which refuses to resolve modules above the inferred project root,
   and `dashboard/package-lock.json` makes it infer `dashboard/`. `next.config.ts` therefore sets
   `turbopack: { root: <repo root> }` **as well as** the requested `experimental.externalDir`
   (still accepted — it is what the webpack builder needs). With both, `import { RunManifest }
   from '@shared/schemas'` compiles and resolves the repo-root `zod` from `shared/`'s own
   `node_modules` lookup — no dependency was added to either package.json.

2. **The default tab is `Log`, not the run's own type tab.** T17 step 4 fixes the tab list but
   not the default. Until T18–T20 land, the three type tabs render "coming soon", so defaulting
   to one of them would mean every run opened onto an empty box; `log.txt` is real content for
   every run of every kind, including ones that died before producing a result block. The type
   tab of the run's kind is still shown first and is one click away. One line in
   `parseTab()` to change when the type views arrive.

3. **Type tabs are hidden-by-dimming, not hidden.** A `review` run shows `Report` and `Design`
   greyed out and unclickable rather than removing them, so the tab bar is the same shape on
   every run and the reader can see what a run of another kind would offer.

4. **`next/font/google` was removed from the generated layout.** It fetches font files at
   build/dev time; the panel is a local tool over a local store and must start with no network.
   Replaced by the system sans/mono stacks, defined as theme variables in `globals.css`.

5. **Light/dark: `prefers-color-scheme` only, with no toggle and no `dark:` variants.** Every
   colour is a CSS variable declared twice (once on `:root`, once in the media query) and
   exposed to Tailwind through `@theme inline`, so a component can only spell a colour one way.
   The alternative — `dark:` pairs at each call site — is the version where one pair eventually
   goes unpaired and a panel becomes unreadable at night.

6. **Extras beyond the step list, all generic (not T18–T20 work):** the run header lists the
   run's artifacts as `/api/artifact` links, derived from whichever result block the manifest
   happens to carry — without it nothing in the UI exercised the artifact route. Home also shows
   any run-bearing directory that `workspaces.json` has forgotten (marked "not in
   workspaces.json"), because its runs already appear under "latest runs" and a workspace that
   is half-visible is worse than one that is fully visible. A themed `not-found.tsx` catches the
   `notFound()` calls.

7. **`/api/artifact` content types are an allow-list, not a lookup.** `.html` and `.svg` are
   deliberately absent and fall back to `application/octet-stream` with `X-Content-Type-Options:
   nosniff`: artifacts are agent-generated, and serving one as HTML from the panel's own origin
   would let it run script there. Files are streamed (`Readable.toWeb`) rather than buffered,
   for design-loop videos.

8. **`next build` warns twice about "Dynamic filesystem access causes tracing of the whole
   project"** at the `awHome()` calls. The warning concerns which source files get copied into a
   deployment bundle; here the store is an absolute path from `$AW_HOME` chosen at run time and
   outside the project, so there is nothing to trace. Left as-is with the reasoning recorded in
   `src/lib/store.ts`'s header rather than papered over with `turbopackIgnore` comments at every
   call site. The build itself succeeds.

9. **The five unused `public/*.svg` files from the template were deleted** and the generated
   README replaced with one describing the panel. `dashboard/AGENTS.md` and `dashboard/CLAUDE.md`
   were left alone — `next dev` rewrites `AGENTS.md` on every start, so removing it only
   re-creates it.

10. **The hostile fixture for the confinement probes lives in a scratch directory, not the real
    store.** Next 16 refuses to start a second `next dev` in the same directory, so the security
    pass ran the same server with `AW_HOME` pointed at the fixture and the visual pass ran it
    against `~/.agent-workflows`. Nothing was written to the real store — no symlinks, no
    synthetic manifests. The four-status badge screenshots come from that scratch store too,
    because all five real runs finished `done`.

11. **Step 3's `readArtifact(ws, id, relPath)` is `resolveArtifact(ws, id, relPath)`,** which
    returns a descriptor (`absPath`, `relPath`, `size`, `contentType`, `fileName`) or `null` and
    never reads the file; the read is `fs.createReadStream` in `/api/artifact`. The step's
    requirement — "resolve + REJECT paths escaping the run dir" — is met in full and in one
    place; only the read was moved to the caller, because the alternative is buffering a
    design-loop video into memory to hand it to a `<video>` tag (deviation 7).

12. **The panel binds `127.0.0.1`, not every interface.** `next dev`/`next start` with no `-H`
    bind `0.0.0.0`, which put the whole store on the LAN with no authentication: every run's
    `log.txt` — which mirrors tool-call inputs, including an `http_request` login body built
    from `app.testAccount` — plus `manifest.json`, `diff.patch` and every artifact, readable by
    anyone on the same wifi. `dashboard/package.json` now passes `-H 127.0.0.1` in both scripts,
    so those requests are refused at the socket. This matches what the panel already claims to
    be (a local tool over a local store, deviation 4).

13. **Path confinement is anchored on the resolved `$AW_HOME`, not on the run directory.** The
    original gate 4 compared `realpath(target)` against `realpath(runDir)` — which, when the run
    or workspace DIRECTORY was itself a symlink, is the escaped location on both sides: a
    `$AW_HOME/<ws>/runs/<id>` symlinked to `/etc` served `/etc/passwd` through `/api/artifact`
    (and never appeared in any listing, because `readdirSync` reports a symlink as not a
    directory). `realRunDir()` now resolves the run directory and requires it to still sit
    inside the resolved store root; `resolveArtifact`, `readLogTail` and `readRun` all go
    through it, so the API, the log tab and the run page share one gate.

14. **`readLogTail` tails by BYTES (last 1 MB), and reports a read failure as a read failure.**
    Reading the whole file to keep its last 500 lines cost its full size in server memory on
    every uncached request, and past V8's ~512 MB string limit it threw — which the `catch`
    turned into "This run has no log.txt" for a log that was merely enormous. The tail now stats
    the file, reads at most the last megabyte, drops the first (partial) line, and returns
    `totalLines: null` when the count is unknown; the Log tab then says "last N lines of 586.5
    MB", and an unreadable-but-present log says so with its size.

15. **A registry entry whose name is not a safe path segment is shown unlinked, not linked.**
    `listWorkspaceSummaries()` was taking registry names verbatim while `runsDir()` validated
    them, so a hand-edited `workspaces.json` with `"my workspace"` produced a home card and a
    header link that both 404. Summaries now carry `usable`; the header drops those entries and
    home renders them as a dashed, unlinked card reading "name is not a valid directory segment
    — the CLI cannot use this workspace".

16. **Three scans of the store per home render became one.** `listWorkspaceSummaries()` is
    wrapped in React's `cache()`, so `SiteHeader` (rendered on every route) and the page it
    wraps share a single pass instead of each re-reading and zod-parsing every manifest under
    `$AW_HOME`. The workspace run table is also capped at the newest 100 with a "showing the
    newest 100 of N — show all" line (`?limit=all`), matching what home already did at 20; it
    was rendering every run a workspace had ever recorded, uncached, on every reload.

17. **The run header resolves each artifact before linking it.** `manifestArtifacts()` returns
    `present`, and a path the manifest names but the store does not have renders struck-through
    with "(file missing)" instead of a link that answers 404 — the state a deleted artifact, or
    T16's "record the intended path rather than fail the run" behaviour, leaves behind.

18. **`/api/artifact` answers a single `bytes=` Range with 206 and advertises `accept-ranges`.**
    ~20 lines over a positioned `createReadStream`. The route already streams for the sake of
    design-loop videos; a `<video>` that cannot seek is the other half of that, and T20 would
    have had to reopen this route for it.

19. **Not fixed, deliberately:** a `running` manifest left by `SIGKILL` still shows as a live
    run with no age hint (badging a stale one needs run mtime plumbed through `listRuns` into
    `RunTable`, and the threshold is a product decision), and run directories the panel cannot
    read (corrupt or absent `manifest.json`) are still silently skipped rather than counted in a
    "N run directories could not be read" line. Both are recorded here as known gaps.
