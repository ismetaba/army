# T20 — Design gallery

Depends on: T17. Read first: `tasks/SPEC.md` (ScreenShot, artifacts layout).
Goal: screenshots/videos reviewable per feature; feedback captured for the iterate loop.

## Steps

1. Run page `Design` tab (only when `manifest.design` exists):
   - Screen grid grouped by `screen`: mobile and desktop images side by side
     (`/api/artifact` URLs), click → full-size lightbox (plain fixed-position overlay,
     ESC/click closes). `max-width:100%`, retain aspect.
   - Judgment calls list + feedbackHistory (numbered, latest last).
   - If `manifest.design.video` exists: `<video controls>` via `/api/artifact`.
2. Run-over-run compare: dropdown listing other `design-loop` runs with the same feature
   slug; choosing one renders each screen as "then vs now" image pairs per viewport.
3. Feedback box (client component) at the bottom: textarea + "Queue feedback" button →
   `POST /api/feedback { ws, runId, text }` which appends to
   `<runDir>/feedback-queue.json` (array of `{ text, createdAt }`). Under the box, render
   the queued items and the exact command to apply them:
   `npx tsx src/cli.ts design-loop "<feature>" --iterate "<text>" --workspace <ws>`
   with a copy button. (Actual in-UI triggering arrives in T22 — this task only queues and
   hands over the command.)

## Acceptance

With a real T10+T16 run (≥2 screens):
1. Grid shows both viewports per screen; lightbox opens/closes; images load via /api/artifact.
2. Compare mode shows then/now pairs against an older run of the same feature.
3. Queued feedback persists (`feedback-queue.json`) and survives reload; the copyable
   `--iterate` command contains the queued text verbatim.

## Out of scope
No spawn/trigger (T22). No image diffing/overlay.

## Files

- `dashboard/src/components/design-data.ts` — pure helpers (grouping, compare unions, shell
  quoting, the `--iterate` command, feedback validation, queue parsing) + `design-data.test.ts`.
- `dashboard/src/components/design-panel.tsx` — server half: resolves every screenshot, the video
  and `feedback-queue.json` through `resolveArtifact`, finds the runs to compare against.
- `dashboard/src/components/design-gallery.tsx` — client: grid, lightbox, compare dropdown, video.
- `dashboard/src/components/design-feedback.tsx` — client: textarea, queue list, copyable commands.
- `dashboard/src/app/api/feedback/route.ts` — `POST /api/feedback`, the panel's only write path.
- `dashboard/src/app/ws/[ws]/run/[id]/page.tsx` — the `design` branch now mounts `DesignPanel`.

## Deviations

1. **The copyable command uses POSIX single quotes, not the double quotes in step 3.** Both the
   feature (agent-written) and the feedback (typed into the panel) are untrusted, and inside
   double quotes `$(…)`, backticks and `$VAR` still execute when the line is pasted. Single
   quotes make the whole argument literal (`'` → `'\''`), which is what SPEC § Dashboard security
   invariants #3 requires of run content that reaches a shell. The workspace name is quoted too.
2. **`--video` is not re-emitted** in the copied command even for a run that used it: it records
   the session rather than describing the feature, and a copied command that silently starts a
   screen recording is a surprise.
3. **Extra command: "all N in one run".** `--iterate` takes a single string
   (`src/commands/design-loop.ts`), so several queued notes are several runs; the numbered
   combined command is offered as the alternative rather than pretending `--iterate` repeats.
4. **`/api/feedback` duplicates `realRunDir`.** `dashboard/src/lib/store.ts` keeps it private and
   store.ts is outside this task's scope, so the route repeats the two `realpath` calls and the
   containment check instead of exporting it. `readRun` still applies the original first.
5. **Hardening beyond the step:** the route requires `content-type: application/json` and rejects
   a mismatched (or `null`) `Origin` — together the CSRF defence for a panel with no login — and
   caps one item at 2000 characters, the queue at 50 items and the file at 256 kB. It also
   rejects C0 control characters: an ESC in a queued note is an ANSI sequence that a terminal
   acts on when the copied command echoes, which quoting does not address.
   The origin check compares against the `Host` HEADER, because `next dev` rewrites
   `request.url` to `localhost:4400` however the browser actually reached it.
6. **Writes are serialised per run directory** (an in-process promise chain) on top of the
   tmp+rename write. Rename alone stops a reader seeing a truncated file; it does not stop two
   overlapping requests losing one item between read and write.
7. **A `feedback-queue.json` that does not parse is never overwritten** — the box disables itself
   and the route answers 409. Clobbering it would destroy whatever it holds.
8. **`ComingSoon` was deleted from the run page.** With T18–T20 landed nothing referenced it and
   eslint fails on an unused function. The default tab is deliberately still `log`: switching it
   to the run's own kind would change every review and test-feature page, which is not T20's.
9. **`design-data.ts` imports `slugify` from `./report-data` with a relative path**, not the `@/`
   alias. Root vitest has no path aliases (the existing dashboard tests import relatively and get
   away with `@shared/*` only because those imports are `import type`).
10. **Plain `<img>`, not `next/image`.** The optimiser would re-fetch and cache a local artifact
    that `/api/artifact` already streams `no-store`, and would need config for its own loader.
11. **The compare list is capped at 20 candidates and restricted to the same workspace**
    (`design-panel.tsx`: `MAX_COMPARE_RUNS`, `listRuns(run.workspace)`). Step 2 says "other
    `design-loop` runs with the same feature slug"; both limits narrow that. The cap keeps the
    dropdown and the manifest reads bounded on a feature iterated on for weeks, and a run in
    another workspace was designed against a different repo, so "the same feature" is not the
    same thing. Recorded here because they were argued only in code comments before.

## Corrections (2026-08-22, review follow-up)

Deviations 4, 5 and 7 above no longer describe the code, and are superseded:

- **4 is withdrawn.** `realRunDir` is now EXPORTED from `dashboard/src/lib/store.ts` and the
  route's private copy (with its own `isInside`) is gone. The scope argument behind the
  duplication stopped holding once T21 extended store.ts anyway, and two copies of a containment
  check are two places to fix when the rule changes.
- **5 is superseded by the shared guard.** The route now calls `guardMutation` from
  `@/lib/api-guard` like every other mutating route, so it gains the `Sec-Fetch-Site` check it was
  missing (a `Sec-Fetch-Site: cross-site` POST used to be accepted and written) and answers
  `{ ok: false, message }` like the rest of the panel instead of `{ ok: false, error }`. The extra
  strictness this deviation claimed — refusing `Origin: null` — was moved INTO `guardMutation`, so
  every route has it now. The `Host`-header comparison it describes was the whole of the panel's
  CSRF defence and is defeated by DNS rebinding; `guardHost` pins the Host to a loopback name in
  front of it. A `content-length` cap (16 kB) was added so a 10 MB body is refused before it is
  parsed rather than after.
- **7 is now true of more files than it claimed.** The read-modify-write uses
  `strictFeedbackQueue`, not the lenient display parser: a queue that *does* parse but holds a
  record the panel would narrow (a note with no `createdAt`, an entry carrying `appliedAt`) is
  refused with the same 409, instead of being silently rewritten without it.
- **The write target is the REQUEST's `ws`/`runId`, not the manifest's.** A manifest declaring
  another run's id used to redirect the write into that run's directory. `loadManifest` in
  store.ts now derives `runId`/`workspace` from the directory it read the file from, so a manifest
  cannot misdescribe itself anywhere in the panel.
- **`designFeature` calls `featureLabel`** from `report-data.ts` rather than re-deriving two of
  its three branches. A run recorded as `design-loop add-footer --workspace fixture` used to yield
  "" here and "add-footer" on the Report tab.
- **The compare dropdown works on a run with no screenshots.** The `groups.length === 0` branch
  short-circuited before `against`, which made the control dead on exactly the run a comparison is
  most useful for.
