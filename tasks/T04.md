# T04 — `aw ping` smoke command

Depends on: T03. Read first: `tasks/SPEC.md` (CLI commands).
Goal: verify each provider answers a one-prompt round trip, with readable failures.

## Steps

1. Create `src/commands/ping.ts` exporting `registerPing(program: Command)`:
   - Options: `--provider <p>` (default `lmstudio`), `--model <m>`, `--config <path>`.
   - Model resolution: if `--model` missing, try `loadConfig` (ignore load errors and then
     REQUIRE `--model` for providers other than defaults) → `resolveModel('code-reviewer', flags, cfg)`
     is NOT used here; ping resolves directly: flags → config.defaults.
   - For provider `claude-cli`: instead of `getModel`, run
     `claude -p "Reply with exactly: pong" --output-format text` via `child_process.execFile`
     with 60 s timeout; treat non-zero exit or "Not logged in" in output as failure and print
     the known fix: run `claude` interactively once, or use provider `anthropic`.
   - Other providers: `const t0 = Date.now(); const r = await generateText({ model, prompt: 'Reply with exactly: pong' });`
     then print one line: `OK <provider> <model> <ms>ms — "<first 40 chars of r.text>"`.
   - Error mapping: `ECONNREFUSED` or `fetch failed` on lmstudio →
     `LM Studio is not reachable at <baseURL>. Start LM Studio and enable the local server.`;
     missing env key → the requireEnv message. Always exit 1 on failure.
2. Register in `src/cli.ts`: `registerPing(program)`.

## Acceptance

```
npx tsx src/cli.ts ping --provider lmstudio --model <id loaded in LM Studio>   # OK line
npx tsx src/cli.ts ping --provider anthropic --model claude-sonnet-5           # OK line (key set)
npx tsx src/cli.ts ping --provider openai --model gpt-5                        # OK line, or clear key error
npx tsx src/cli.ts ping --provider claude-cli                                  # OK or documented "Not logged in" message
```
At minimum lmstudio AND one cloud provider must return OK; the other two must fail with
the exact readable messages above (not stack traces).

## Out of scope
No tools, no workflows.

## Deviations

1. **`openai` / `anthropic` cannot return an OK line on this machine** — neither API key exists
   (no `.env`, both vars unset), so the missing-key path was verified instead of a live call:
   `OPENAI_API_KEY is not set (add it to .env)` / `ANTHROPIC_API_KEY is not set (add it to .env)`,
   exit 1, no stack. To prove the key check is the *only* blocker, both were re-run with a bogus
   key and reached the real API, failing with a one-line readable message (openai:
   `Incorrect API key provided: ...`; anthropic: `API key is invalid.`), exit 1.
   Acceptance's "at minimum lmstudio AND one cloud provider must return OK" is therefore met as
   lmstudio + claude-cli; the two cloud providers fail readably as required.
2. **`--provider` default is a fallback, not a commander default.** Step 1 asks for both
   "default `lmstudio`" and "flags → config.defaults"; a commander-level default would make
   `config.defaults.provider` unreachable. Resolution order is
   `--provider` → `config.defaults.provider` → `lmstudio`, and the help text says so.
3. **"ignore load errors" is scoped to a missing implicit config.** `loadConfig` prints and
   `process.exit(1)`s rather than throwing, so it cannot be caught. Ping therefore skips an
   absent `./aw.config.json` (via `fs.existsSync`) and requires `--model`; an *explicit*
   `--config <path>` is loaded strictly, so a wrong path fails loudly (`config not found: ...`).
4. **Model-required message drops the agent clause.** Ping resolves no agent, so SPEC's message
   is used without the `agents.<name>.model` half:
   `model required: provider "<p>" selected without a model (use --model)`.
5. **`claude-cli` model label.** `claude -p` takes no model id, so the OK line prints the
   `--model` value when one is passed and `default` otherwise:
   `OK claude-cli default 7639ms — "pong"`.
6. **Added env `AW_CLAUDE_BIN`** (default `claude`) to override the binary. Its only purpose is
   to let the "Not logged in" and "binary not found" failure paths be exercised against a stub
   script; normal use is unaffected.
7. **`maxRetries: 0` on `generateText`.** Without it the AI SDK retried three times and replaced
   the transport error with `Failed after 3 attempts. Last error: ...`, hiding the friendly
   LM Studio message. A smoke test reports the first failure.
8. **Connection-failure detection also matches `Cannot connect to API` and `bad port`.** The AI
   SDK re-words `ECONNREFUSED` as `Cannot connect to API: ...`, and a WHATWG-blocked port such as
   the suggested `:9` never reaches `connect()` at all (`bad port`). Both now map to
   `LM Studio is not reachable at <baseURL>. Start LM Studio and enable the local server.`
   Verified against `:9` and against `:1235` (a real ECONNREFUSED).
9. **120 s abort guard** on `generateText`, so a provider that accepts the request and never
   answers fails with `<provider> did not answer within 120s (model "<m>")` instead of hanging.
10. **OK-line preview collapses whitespace** before the 40-character slice, so a multi-line answer
    cannot break the single-line format. It also strips C0/C1 control characters first: `\s` does
    not cover ESC, so a model answering with ANSI escapes could otherwise write them straight into
    a status line that starts with `OK`.

### Follow-up review fixes (spec-conformance pass)

11. **The 120 s timeout message is decided by the signal, not by the error text.** `isAbort()`
    regex-matched `/aborted|timed? ?out/i` over the whole error chain, so a *provider-side*
    error such as LM Studio's `Prediction timed out after 300 seconds` or
    `Request timed out while waiting for the model to load` was replaced by the false
    `lmstudio did not answer within 120s` — after ~30 ms — discarding the only diagnostic the
    smoke test exists to produce. The `AbortSignal` is now held in a local and
    `describeFailure()` reports the client timeout only when `signal.aborted` (or the top-level
    error is `AbortError`/`TimeoutError`); everything else falls through to `err.message`.

12. **An empty completion is a failure, not an OK line.** `generateText` returning `""` (a
    reasoning-only model that puts its answer in `reasoning_content`, or a provider returning
    `content: null`) printed `OK … — ""` and exited 0, so a broken provider config passed the
    smoke test. It now fails with
    `<provider> returned no text (model "<m>"). The request succeeded but the answer was empty …`,
    exit 1 — the same rule the `claude-cli` branch already applied.

13. **An explicit `--config <path>` is always loaded** (this is what Deviation 3 claimed).
    The old short-circuit skipped it whenever `--provider` and `--model` were both given, so a
    typo'd path was silently ignored in one invocation and reported in another. Only the implicit
    `./aw.config.json` is skipped now.

14. **The `claude` child is killed when ping itself is signalled.** SIGINT/SIGTERM aimed at the
    node process alone left `claude` running, reparented to init (T16 supervises ping
    programmatically, where the terminal does not signal the whole process group). The handler
    sends SIGTERM to the child and exits 130/143, since registering a signal listener disables
    node's default "die on SIGINT".

15. **`tasks/BACKLOG.md` checkbox left unticked.** Reported by the review, but the fix pass was
    explicitly scoped to exclude `tasks/BACKLOG.md`, so the box is untouched here.
