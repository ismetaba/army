# T01 — Scaffold TypeScript project

Depends on: none. Read first: `tasks/SPEC.md`.
Goal: runnable TS skeleton with all runtime deps installed and a CLI stub.

## Steps

1. In the repo root run:
   ```
   npm init -y
   npm install ai @ai-sdk/openai @ai-sdk/anthropic ai-sdk-provider-claude-code zod commander dotenv gray-matter
   npm install -D typescript tsx vitest @types/node
   npm install playwright
   npx playwright install chromium
   ```
2. Edit `package.json`: set `"name": "agent-workflows"`, `"private": true`, `"type": "module"`,
   and replace `scripts` with:
   ```json
   {
     "aw": "tsx src/cli.ts",
     "typecheck": "tsc --noEmit",
     "test": "vitest run"
   }
   ```
3. Create `tsconfig.json`:
   ```json
   {
     "compilerOptions": {
       "target": "ES2022", "module": "ESNext", "moduleResolution": "Bundler",
       "strict": true, "skipLibCheck": true, "esModuleInterop": true,
       "resolveJsonModule": true, "types": ["node"], "noEmit": true
     },
     "include": ["src", "shared", "scripts"]
   }
   ```
4. Create `src/cli.ts`:
   ```ts
   import { Command } from 'commander';
   const program = new Command();
   program.name('aw').description('Provider-selectable agent workflows: design-loop, test-feature, review');
   // subcommands are registered here by later tasks (T04, T08, T09, T10, T13)
   program.parse();
   ```
5. Create `.env.example` with exactly:
   ```
   OPENAI_API_KEY=
   ANTHROPIC_API_KEY=
   LMSTUDIO_BASE_URL=http://localhost:1234/v1
   AW_TEST_PASSWORD=
   ```
6. Append to `.gitignore` (keep existing lines): `node_modules/`, `dist/`, `.next/`,
   `test-results/`, `*.local` — one per line, skip any line already present.

## Acceptance

```
npx tsx src/cli.ts --help        # prints name "aw" + description, exit 0
npm run typecheck                # no errors
```

## Out of scope
No providers, no tools, no workflow logic. Do not create `shared/schemas.ts` yet (T03).

## Deviations
- Installed versions are newer than SPEC assumed: `ai` **7.0.74** (SPEC said AI SDK v6),
  `@ai-sdk/openai` 4.0.45, `@ai-sdk/anthropic` 4.0.40, `zod` 4.4.3, `typescript` 7.0.2,
  `vitest` 4.1.11, `playwright` 1.62.1. Verified the API surface SPEC relies on still exists
  in `ai@7`: `tool({ description, inputSchema, execute })`, `generateText`, `stepCountIs`,
  `generateObject`; `openai(id)` / `anthropic(id)` are callable; `createOpenAI({ baseURL })`
  exists. No SPEC change needed.
- `ai-sdk-provider-claude-code@4.1.1` also exports `tool`, `createSdkMcpServer`,
  `createAiSdkMcpServer`, so the "no tool execution" limitation was re-checked empirically
  (probe: `generateText` with a real `execute` tool via `claudeCode('sonnet')`):
  **tools are silently IGNORED** — `TOOL_EXECUTED_TIMES: 0`, the model answered from memory,
  and the provider only emitted a warning: *"The feature 'tools' is not supported. The Claude
  Code CLI executes its own tools; AI SDK tools cannot be auto-bridged at the provider layer
  and will be ignored."* SPEC's limitation therefore STANDS, and the hard refusal of
  `claude-cli` in CLI workflows is required — a silent ignore would produce confidently wrong
  results. (Escape hatch for a future enhancement, not in scope: expose tools through
  `createAiSdkMcpServer` + the `mcpServers`/`allowedTools` settings.)
