# T03 — Provider registry + config resolution

Depends on: T01. Read first: `tasks/SPEC.md` (Types, Model resolution, example config).
Goal: one `getModel()` for all 4 providers; config loading with documented precedence.

## Steps

1. Create `shared/schemas.ts` with EXACTLY the code from SPEC.md § Types.
2. Create `src/providers/index.ts`:
   ```ts
   import 'dotenv/config';
   import { createOpenAI, openai } from '@ai-sdk/openai';
   import { anthropic } from '@ai-sdk/anthropic';
   import type { ProviderId } from '../../shared/schemas';

   function requireEnv(name: string): void {
     if (!process.env[name]) throw new Error(`${name} is not set (add it to .env)`);
   }

   export function getModel(provider: ProviderId, modelId: string) {
     switch (provider) {
       case 'lmstudio': {
         const lmstudio = createOpenAI({
           baseURL: process.env.LMSTUDIO_BASE_URL ?? 'http://localhost:1234/v1',
           apiKey: 'lm-studio',
         });
         return lmstudio(modelId);
       }
       case 'openai': requireEnv('OPENAI_API_KEY'); return openai(modelId);
       case 'anthropic': requireEnv('ANTHROPIC_API_KEY'); return anthropic(modelId);
       case 'claude-cli': {
         // Import lazily; check the package README/types for the exact factory export
         // (expected: `claudeCode`). No API key needed — uses the local Claude Code login.
         throw new Error('claude-cli supports no AI SDK tool execution — use provider "anthropic" for CLI workflows, or the .claude/ native path. (ping may still implement it: see T04)');
       }
     }
   }
   ```
3. Create `src/config.ts` exporting:
   - `loadConfig(opts: { config?: string; workspace?: string }): AwConfig` — reads
     `opts.config ?? './aw.config.json'`; if `opts.workspace` given, look up `repoRoot` in
     `$AW_HOME/workspaces.json` (default `~/.agent-workflows/`) and read
     `<repoRoot>/aw.config.json`. Validate with `AwConfig.parse`; on failure print zod
     issues and exit 1.
   - `resolveModel(agent: AgentName, flags: { provider?: string; model?: string }, cfg: AwConfig): { provider: ProviderId; model: string }`
     implementing SPEC § Model resolution EXACTLY, including the
     "model required: provider …" error.
4. Create `aw.config.example.json` with EXACTLY the JSON from SPEC § aw.config.example.json.
5. Create `src/config.test.ts` (vitest) covering: flag wins over agent entry; agent entry
   wins over defaults; provider-without-model error; defaults used when nothing else set.
   Build configs inline in the test (no fs).

## Acceptance

```
npm run typecheck
npm run test          # config tests pass
```

## Out of scope
No network calls (T04). Do not implement the claude-cli SDK path beyond the explicit error.

## Deviations

1. **`z.partialRecord` instead of `z.record` (required minimal fix).** SPEC § Types spells the
   per-agent overrides `z.record(AgentName, ModelChoice.partial())`. In zod@4 `z.record(<enum>, v)`
   requires *every* enum key to be present, which would make the optional overrides mandatory.
   `shared/schemas.ts` uses `z.partialRecord(AgentName, ModelChoice.partial())`; everything else in
   the Types block is verbatim.
2. **`src/util.ts` added** with `awHome()` (`$AW_HOME` → else `~/.agent-workflows`, per SPEC § Storage),
   used by `loadConfig`'s `--workspace` lookup. Explicitly permitted by the task scope.
3. **`--provider` flag is validated.** Step 3's signature types the flag as `provider?: string`, so
   `resolveModel` parses it with `ProviderId` and throws
   `unknown provider "<v>" (expected one of: lmstudio, openai, anthropic, claude-cli)` rather than
   letting an unknown string reach `getModel`. Empty/whitespace-only flag values are treated as absent.
4. **Error style split.** `loadConfig` prints a readable message (+ `path: message` per zod issue) to
   stderr and `process.exit(1)` — it never throws a raw stack. `resolveModel` throws a `ConfigError`
   (exported) instead of exiting, so the precedence rules are unit-testable; the CLI prints
   `err.message` and exits 1.
5. **`src/config.test.ts` also validates `aw.config.example.json`.** Step 5 says to build configs
   inline with no fs; that still holds for every precedence test. One extra `describe` block reads the
   shipped example file and asserts it parses with `AwConfig`, per the acceptance requirement to prove
   the example config is valid.
6. `resolveConfigPath` is exported alongside `loadConfig` (same file) so later tasks can report which
   config path was used without re-implementing the workspace lookup.
