# T12 — Headless `/review` verification

Depends on: T11. Read first: `tasks/SPEC.md` (known risks in PLAN.md § Known risks).
Goal: confirm (or document the workaround for) `claude -p "/review"`.

## Steps

1. In this repo (or any target repo where `.claude/` is installed), create a branch with a
   small change, then run:
   ```
   claude -p "/review main" --output-format text
   ```
   with a 5-minute timeout.
2. Outcome A — it prints a `VERDICT:` review: record the exact command in README under a new
   `## Headless review` section, including "add to CI/hooks as needed".
3. Outcome B — output contains `Not logged in` (known macOS Keychain issue for spawned
   processes) or auth errors: do NOT loop retries. Add to README `## Headless review`:
   - the failure verbatim,
   - workaround 1: run `claude` interactively once in the same shell/session first,
   - workaround 2 (always works): `npx tsx src/cli.ts review --base main --provider anthropic --model claude-sonnet-5`.
4. Either way, add a one-line pointer to this section from `CLAUDE.md` § Commands.

## Acceptance

- README `## Headless review` section exists and matches what actually happened on this
  machine (paste the real output snippet, truncated to 10 lines).
- The documented working command (native or fallback) was actually run and produced a verdict.

## Deviations

1. **Outcome A, so step 3's Outcome-B text is not in README as a failure report.** `Not logged in`
   never appeared. Both workarounds are still recorded, but as a one-paragraph "if it ever
   happens" note rather than as this machine's result — writing them up as the observed outcome
   would have been false.

2. **The step-3 fallback command is documented in a corrected form.** As written
   (`npx tsx src/cli.ts review --base main --provider anthropic --model claude-sonnet-5`) it fails
   twice on this machine: there is no `ANTHROPIC_API_KEY` (Run 4 above), and with no `--config` it
   would read `./aw.config.json` — which does not exist in the toolkit repo, only
   `aw.config.example.json`. README therefore documents
   `npx tsx src/cli.ts review --base main --config <target>/aw.config.json` (verified, Run 3) and
   mentions the `--provider anthropic --model claude-sonnet-5` override plus the exact error you
   get without a key.

3. **The native command must be run from the target repo, and the target repo needs the two
   generated files.** T12 step 1 says "any target repo where `.claude/` is installed" but nothing
   installs it yet (T13). README spells out the copy step; the fixture run needed it.

4. **Exit codes are documented as differing between the two paths.** Verified: the native run
   returned `exit=0` while reporting two BLOCKERs (a slash command cannot set an exit code), so
   "add to CI/hooks as needed" in README comes with the grep-based gate for the native path and
   points at the CLI (`2` = BLOCKER, SPEC § exit codes) for a real gate. Without this note the
   documented CI advice would be actively misleading.

5. **`CLAUDE.md` § Commands already carried the pointer** (`- Headless review: see README §
   Headless review`, committed in the T01–T03 scaffold), so no edit was needed there; the section
   it points at now exists.

6. **`--output-format json` was run a second time only to measure the run** (duration, turns) so
   README's "how long does this take" advice is measured rather than guessed. It reviewed the same
   branch and reproduced the same verdict.

7. **The README CI/hook gate failed closed and has been rewritten (2026-08-21).** The recommended
   one-liner `out=$(claude -p "/review main" --output-format text); grep -q '^\[BLOCKER\]' <<<"$out"
   && exit 1` exits with *grep's* status when it is a script's last statement, so a clean review
   exited 1 and blocked every push — and `out=$(claude …)` discarded the CLI's own status, so a
   run that failed outright produced empty output and would have passed the gate. Reproduced both
   ways (clean → exit 1, blocker → exit 1: the gate could not tell apart the two cases it exists
   for). README now shows a full script that checks the CLI's status with `if ! out=$(…)` and ends
   in an explicit `exit 0`; re-verified: clean → 0, blocker → 1.

8. **The README exit-code bullet now states the `APPROVE` suppression.** `src/commands/review.ts`
   sets exit 2 only when the verdict is not `APPROVE` (T08 Deviation 15); an `APPROVE` that still
   lists a BLOCKER exits 0 with a stderr warning, which a CI gate discards. The bullet said only
   "`2` a BLOCKER was reported".

9. **The § Result claim that the fixture's copied `.claude/` files were removed was not true when
   written.** Adversarial verification found `/Users/matt/Test/aw-fixture` still on `bug/planted`
   with an untracked `.claude/` holding byte-identical copies of `commands/review.md` and
   `agents/code-reviewer.md`; it restored the fixture. Recorded here because § Result is outside
   this run's editable scope, and because T13's "`aw init` copies these" acceptance can pass
   spuriously against a fixture that already contains the copies. Verified at the end of this run:
   fixture on `main`, `git status --porcelain` empty, `bug/planted` and `aw-t10-live` intact, no
   `.claude/` directory.
