# T05 — Core tools with per-agent permission profiles

Depends on: T03. Read first: `tasks/SPEC.md` (Tools table, blocked patterns).
Goal: one tool implementation set; profiles decide which tools an agent gets and what they may touch.

## Steps

1. Create `src/tools/core.ts`. Export
   `makeCoreTools(profile: 'designer' | 'tester' | 'reviewer', repoRoot: string)` returning an
   AI SDK tools object (`Record<string, Tool>` built with `tool({ description, inputSchema, execute })`;
   if the installed `ai` version names it `parameters`, use that). Implement:
   - `read_file { path, offset?, limit? }` → numbered lines; path must resolve inside `repoRoot`.
   - `glob { pattern }` → file list via `fs.promises.glob` or a `find`-based fallback.
   - `grep { pattern, path? }` → `execFile('grep', ['-rn', '-I', '--exclude-dir=node_modules', '--exclude-dir=.git', pattern, path ?? '.'])`,
     cap output at 8 KB, non-match is not an error.
   - `git_diff { base? }` → `git diff <base>...HEAD` if base given, else `git diff HEAD`; plus
     `git_log { limit? }` → `git log --oneline -n <limit ?? 20>`. Both via execFile in `repoRoot`.
   - `write_file { path, content }`, `edit_file { path, old, new }` (exact unique string
     replace; error if 0 or >1 matches).
   - `bash { command, timeoutMs? }` → `exec` with cwd `repoRoot`, timeout default 120 s,
     stdout+stderr capped 8 KB. REJECT any command matching a blocked pattern from SPEC with
     `blocked by guardrails: <pattern>`.
   - `http_request { method, url, headers?, body? }` → global `fetch`, return
     `status`, selected headers, body capped 4 KB. If url host is not
     `localhost`/`127.0.0.1` and method is POST/PUT/PATCH/DELETE and the toolset was created
     without `allowDestructive: true` (add it as a third optional arg) → reject with
     `destructive call to non-local target requires --allow-destructive`.
   - Every execute: wrap errors → return `{ error: string }` (never throw), and truncate all
     returned strings to 8 KB with a `…[truncated]` suffix.
2. Apply the profile EXACTLY per the SPEC tools table:
   - `reviewer`: only read_file, glob, grep, git_diff, git_log.
   - `tester`: everything except write outside `test-reports/tmp/` — write_file/edit_file
     execute must reject paths not under `test-reports/tmp/`.
   - `designer`: all tools.
3. Create `src/tools/core.test.ts` (vitest, use a temp dir as repoRoot): reviewer toolset has
   no `write_file` key; tester `write_file` to `src/x.ts` returns error containing
   `test-reports/tmp`; bash `git push origin main` returns error containing `blocked`;
   `edit_file` with non-unique `old` returns error.
