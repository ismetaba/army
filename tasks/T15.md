### (b) as built (2026-08-22)

`npx tsx src/cli.ts design-loop "<feature>" --video`. `(a)` was not built; nothing in this task
touches git hooks.

**What it does**

- `src/tools/browser.ts` — `BrowserToolsOptions.video?: { dir }`. When set, every context is
  created with `recordVideo: { dir, size: <that viewport> }` (`contextOptions()`, exported so the
  off-state is testable). `closeBrowser()` now closes the contexts, renames each finished
  recording to a deterministic name with `video.saveAs()`, drops Playwright's random
  `page@<hash>.webm` original with `video.delete()`, and returns `RecordedVideo[]`
  (`{ viewport, path, bytes, primary }`). It also takes an optional log sink; the old
  no-argument call still works.
- Names (`videoFileNames()`): the run's video is **`video.webm`** — the desktop recording, since
  every design-loop session must visit desktop and that is the frame the gallery is built for.
  The other viewport is kept beside it as `video-mobile.webm` rather than discarded. A session
  that only ever opened mobile still yields `video.webm`, so the name is predictable whatever the
  agent did.
- `src/workflows/design-loop.ts` — passes `{ dir: screenshotDir }` through, so the video lands
  with the stills. On a `--video` run Chromium is released **before** the checkpoint commit,
  because Playwright only writes the file on context close and `git add -A` would otherwise miss
  it. The primary video is copied into the run as `artifacts/video.webm` (SPEC § Storage names it
  there) and recorded as `design.video`; stdout grows a `VIDEO:` block. `DesignLoopResult.video`
  carries the absolute path.
- **Failure paths keep the video too.** `bail()` closes the browser and then saves whatever was
  recorded, so a session that dies (e.g. the `NO_SCREENSHOTS` refusal) still leaves a playable
  `artifacts/video.webm` and a `design.video` on the `error` manifest — that run is precisely the
  one a human wants to watch.
- Nothing is recorded if the agent never opened a browser: no file, no `design.video`, one
  warning line.

## Deviations

- **A second file, `video-mobile.webm`, sits next to `video.webm`.** The offer text said one
  `video.webm`; design-loop drives two independent contexts (mobile + desktop) and Playwright
  records them separately. Merging them would need an encoder — a new dependency, which the task
  forbids — and `RunManifest.design.video` is a single string, so the manifest points at the
  desktop recording under the promised name and the mobile one is kept rather than deleted.
  *(Follow-up fix.)* "Kept" originally meant kept in `screenshots/<slug>/`, which the next
  `--iterate` pass overwrites — the exact loss the T16 screenshot copy exists to prevent. Now
  `saveVideo()` copies **every** recording into the run's `artifacts/` under its own basename;
  `design.video` still names the primary, because the schema holds one.
- **On a `--video` run the browser and dev servers are stopped before the checkpoint**, not
  after. Playwright writes the video on context close, so the old order would have left it out of
  the commit its screenshots are in. A run without the flag keeps the original order exactly.
- **`recordVideo.size` is pinned to the viewport** instead of Playwright's default (scaled to fit
  800×800), so the video matches the screenshots beside it. Cost: a larger file. The pin is exact
  for EVEN dimensions only: VP8 encodes in 2-pixel macroblocks and rounds an odd width down, so
  the default 375×812 mobile viewport records at **374×812** beside 375-wide PNGs. That 1px is the
  encoder, not a defect — the comment on `contextOptions` says so now, so nobody hunts it.
- **A `--video` run deletes every `.webm` in `screenshots/<slug>/` before it starts.** A stale PNG
  is labelled per file on stdout (`(stale — not taken in this run)`); a stale *video* cannot carry
  a label, because it is watched in a player long after that output has scrolled by — and
  `--iterate` reuses the slug, so the previous pass's `video.webm` and `video-mobile.webm` sat
  there unmarked, unlisted, and got committed by the checkpoint's `git add -A` beside fresh
  screenshots. Deleting is safe precisely because `saveVideo()` copies every recording into the
  run's `artifacts/` first, so the earlier pass keeps its evidence somewhere nothing overwrites.
  `page@<hash>.webm` and `video-unsaved-*.webm` are swept too. Helper: `clearRecordings()`.
- **A partial save failure no longer hides the recording that survived.** If only the desktop
  `saveAs` throws, `closeBrowser` reports just the mobile entry and nothing is `primary`;
  `saveVideo()` now falls back to `videos[0]` and the `VIDEO:` block lists every entry, instead of
  printing "(none — Playwright produced no recording for this session)" over a playable file.
  When `saveAs` fails, `closeBrowser` also renames Playwright's random `page@<hash>.webm` to
  `video-unsaved-<viewport>.webm` — deterministic and greppable rather than deleted (it may be the
  only copy) or left to be committed under a name nobody can account for.
- **Offer (b) covers the `aw` CLI only; the `.claude/` native path is deliberately unchanged.**
  The offer names "`--video` flag on `aw design-loop`". The generated `/design-loop` command still
  documents screenshots and no recording, so the two entry points differ in capability on purpose:
  the native path drives Claude Code's own MCP browser tools, which have no `recordVideo`
  equivalent to wire a flag to. If parity is wanted later it belongs in `scripts/sync-claude.ts`
  (T11/T12 own keeping the two paths in step), not here.
- **`closeBrowser()` signature widened** — it now takes an optional log sink and returns
  `RecordedVideo[]`. Existing callers (`test-feature.ts`, `scripts/browser-smoke.ts`) are
  unchanged and unaffected.
- **New test file `src/tools/browser.video.test.ts` launches a real Chromium.** T06 kept real
  browser work in `scripts/browser-smoke.ts`; here the whole feature is "does Playwright actually
  write the file", which no pure function can assert. It adds ~1.5 s to `npm run test`.
