# T15 — Offers (present only; build on request)

Depends on: T14. Read first: `docs/HANDOFF.md` § Step 5.
Goal: offer the two optional extras; build only what the developer explicitly requests.

## Steps

1. Present exactly these two offers to the developer (short, no sales pitch):
   - **(a) pre-push hook** — `.git/hooks/pre-push` (or husky if the target already uses it)
     that runs the T12-documented headless review and blocks the push when exit code is `2`
     (BLOCKER found). Include the caveat: adds ~1–3 min to every push.
   - **(b) design-loop video variant** — `--video` flag on `aw design-loop`: Playwright
     context with `recordVideo: { dir: screenshots/<slug>/ }`, saves `video.webm` alongside
     screenshots (dashboard T20 will play it).
2. If (a) requested: hook script content:
   ```bash
   #!/bin/sh
   echo "aw pre-push review..." >&2
   <documented headless command> ; rc=$?
   [ $rc -eq 2 ] && { echo "push blocked: BLOCKER finding (see review output)" >&2; exit 1; }
   exit 0
   ```
   Install executable; test with a planted BLOCKER (push to a scratch remote or `git push --dry-run` target).
3. If (b) requested: implement in `src/tools/browser.ts` (context option) + `--video` flag in
   T10's command; acceptance = a playable `.webm` appears for a design-loop run.
