# T11 — Claude Code native layer (.claude/), generated from agents/*.md

Depends on: T07–T10. Read first: `tasks/SPEC.md`.
Goal: `/design-loop`, `/test-feature`, `/review` usable inside Claude Code; prompts stay single-source.

## Steps

1. Create `scripts/sync-claude.ts`. It GENERATES `.claude/` from `agents/*.md` (never edit
   `.claude/` by hand — add that as the first line comment in every generated file:
   `<!-- GENERATED by scripts/sync-claude.ts — edit agents/*.md instead -->`).
2. Subagents — for each agent write `.claude/agents/<name>.md`:
   - Frontmatter: `name`, `description` (copied), and `tools:` mapped per profile:
     - reviewer → `Read, Grep, Glob, Bash(git diff:*), Bash(git log:*)`
     - tester → `Read, Grep, Glob, Bash, WebFetch` plus Playwright MCP tools if available
     - designer → `Read, Edit, Write, Grep, Glob, Bash` plus Playwright MCP tools
   - Body: the agent's markdown body + guardrails (same text the CLI loader produces).
3. Commands — write `.claude/commands/`:
   - `review.md`: frontmatter `description`, `argument-hint: [base-branch]`; body: *"Diff
     `${1:-main}...HEAD`, read surrounding context of changed files, then delegate the review
     to the code-reviewer subagent. Output plain text in its VERDICT format. Never ask
     questions (must work under `claude -p`)."*
   - `test-feature.md`: argument-hint `<description> [base-url]`; body encodes T09 steps 2–8
     (reachability→plan→execute via qa-tester subagent→write `test-reports/<slug>-<date>.md`
     →present path + 3-line verdict; destructive-on-non-local requires explicit confirmation).
   - `design-loop.md`: argument-hint `<feature|spec-path>`; body encodes T10 steps 2–8
     (read backend contract → ≤5-line plan → delegate to ui-designer subagent → Playwright
     loop → screenshots to `screenshots/<slug>/<screen>-<viewport>.png` → checkpoint commit,
     never push → present → STOP for feedback; on feedback re-run affected screens only).
   - Each command body must state: Playwright MCP is required for browser steps; if its tools
     are absent, stop and tell the developer to run
     `claude mcp add playwright -- npx @playwright/mcp@latest` (per docs/HANDOFF.md Step 1).
4. Run `npx tsx scripts/sync-claude.ts` and commit the generated `.claude/` output.
5. Add npm script `"sync-claude": "tsx scripts/sync-claude.ts"`.

## Acceptance

1. `npm run sync-claude` is idempotent (second run → `git status` clean).
2. `.claude/agents/` has 3 files, `.claude/commands/` has 3 files, all starting with the
   GENERATED comment; reviewer subagent has no Edit/Write tools.
3. Open a Claude Code session in this repo: `/review`, `/test-feature`, `/design-loop`
   appear in the command list and `/review main` runs (it may report "nothing to review").

## Out of scope
Headless verification is T12. Target-repo installation is T13 (`aw init` copies these).

## Deviations

All of these were verified against the Claude Code build on this machine (native binary,
`@anthropic-ai/claude-code`) with throwaway probe agents/commands in a scratch repo, not assumed.

1. **The GENERATED marker cannot be the first line of the file.** Claude Code expects the YAML
   frontmatter delimiter at line 1; a file starting with
   `<!-- GENERATED by scripts/sync-claude.ts … -->` is silently ignored — the probe agent written
   that way was not registered at all (the session answered `AGENT_MISSING`). The marker is
   therefore emitted as the *first line inside* the frontmatter, as a YAML comment:
   `# GENERATED by scripts/sync-claude.ts — edit agents/*.md instead`. Rewritten that way the same
   probe agent registered and ran, and a probe command with the same marker executed normally.

2. **A subagent's `tools:` is a list of tool NAMES; `Bash(git diff:*)` is not an allow-list.**
   Measured, one probe agent per row (each asked to list the tools it actually had):

   | frontmatter `tools:` | tools the subagent really got |
   |---|---|
   | `Read, Grep, Glob` | `Read, Grep, Glob` |
   | `Read, Grep, Glob, Bash` | `Read, Bash` |
   | `Read, Grep, Glob, Bash(git diff:*), Bash(git log:*)` | `Read, Bash` |
   | `Read, Grep, Glob, Bash, WebFetch, mcp__playwright__browser_*` | `Read, Bash, WebFetch` |

   The scoped form grants the plain, unrestricted `Bash` tool: the probe agent declared with
   `Bash(git diff:*)`/`Bash(git log:*)` ran `touch probe-write.txt`, which was refused only by the
   working-directory sandbox, not by any tool allow-list. Scoping (`Bash(git diff:*)`) is real
   syntax for a **command's** `allowed-tools`, not for an agent's `tools`.

   Consequence: **the code-reviewer subagent is generated with `tools: Read, Grep, Glob` and no
   Bash at all** — T11 step 2's list would have handed the read-only reviewer a full shell, which
   SPEC § Tools and permission profiles forbids. `/review` runs `git diff`/`git log` itself and
   passes the diff, the changed-file list and the truncation notes to the subagent in the prompt.
   `Grep`/`Glob` are still listed for the tester/designer (harmless, forward-compatible) even
   though this build folds them away once `Bash` is granted.

3. **Playwright MCP tools are named explicitly** (`mcp__playwright__browser_navigate`, `…_click`,
   `…_type`, `…_fill_form`, `…_take_screenshot`, `…_resize`, `…_console_messages`, … — 15 names,
   fixed order). Unknown MCP names are ignored by the harness, so the files are valid on a machine
   where the server is not installed yet (verified: the other tools in the same list still loaded).

4. **`/review` also carries `allowed-tools`** beyond the `description` + `argument-hint` T11 asks
   for: `Task, Agent, Read, Grep, Glob` plus read-only `Bash(git …:*)` patterns. It keeps the
   command read-only and pre-approves exactly the git reads it needs, which is what makes it
   usable under `claude -p` without a permission prompt. `/test-feature` and `/design-loop` have no
   `allowed-tools` — they legitimately need Write/Edit, Bash and MCP browser tools.

5. **`.claude/commands/` is the layout T11 specifies and it works**, but the `plugin-dev`
   documentation shipped on this machine now calls it a legacy format and prefers
   `.claude/skills/<name>/SKILL.md`. Both are loaded identically; kept `.claude/commands/` because
   T11 and its acceptance name it. Worth revisiting in T13/T22.

6. `${1:-main}` bash-style defaulting in a command body is supported: `/probe-cmd2` printed
   `base=main` with no argument and `base=develop` with one.

7. **Step 4's "commit the generated `.claude/` output" was not done** — this run is under a hard
   rule against `git commit`/`git push`. `.claude/` is generated and left untracked for the
   developer to commit. The BACKLOG checkbox is likewise left unticked (only this task file may be
   edited in this run).

8. `/design-loop` prints the CLI's exact stop line
   (`--- STOPPING FOR FEEDBACK — resume with: aw design-loop "<feature>" --iterate "<your feedback>" ---`,
   `resumeLine()` in `src/workflows/design-loop.ts`) and adds one sentence saying that inside a
   Claude Code session the developer can simply reply with the feedback, which re-runs the
   affected screens only.

9. **Extras not asked for by T11:** `scripts/sync-claude.ts --check` (exits 1 when `.claude/` is
   stale — for CI and T12) and `scripts/sync-claude.test.ts` (14 vitest cases pinning the marker
   position, the reviewer's tool-less frontmatter, the report/screenshot/checkpoint conventions in
   the command bodies, and idempotence). The generator also refuses to overwrite or prune any file
   in `.claude/` that does not carry the marker, so hand-written additions survive a sync.

10. **`/review` deliberately carries the "no browser tools needed" variant of T11 step 3's
   Playwright sentence.** The step asks every command body to state that Playwright MCP is
   required and to name `claude mcp add playwright -- npx @playwright/mcp@latest`; `/review` has
   no browser step, so it says instead: *"It needs no browser tools — only /design-loop and
   /test-feature require the Playwright MCP server."* Recorded here so a later reader does not
   read it as an omission. `scripts/sync-claude.test.ts` pins the mcp-add string for the other two
   commands only.

11. **The tester profile carries `Write` and withholds `Edit` (2026-08-21).** SPEC § Tools and
   permission profiles gives the tester `write_file`/`edit_file` scoped to `test-reports/tmp/`.
   `PROFILE_TOOLS.tester` granted **neither**, while `NATIVE_NOTES.tester` told the subagent to
   use Write/Edit — so a qa-tester following its own prompt called a tool it did not have and fell
   back to Bash heredocs. `Write` is now granted (the harness has no path scoping, so the
   `test-reports/tmp/` limit stays a prompt rule) and `Edit` is deliberately not: the tester
   creates throwaway files and never changes an existing one. The note says exactly that, and the
   test asserts both halves instead of the vacuous `not.toContain('Edit')` it had before.

12. **The `≤ 40 chars` slug caps in the command bodies were invented and wrong (2026-08-21).**
   `src/workflows/test-feature.ts` caps the report slug at 80 and `src/workflows/design-loop.ts`
   caps the screenshot-directory slug at 60, so `/test-feature` and `aw test-feature` named the
   same run's artifacts differently for any description over 40 characters. Both constants are now
   exported and imported by `scripts/sync-claude.ts`, which interpolates them into the command
   bodies; `scripts/sync-claude.test.ts` pins the generated text against the constants, so the two
   numbers cannot drift apart again.

13. **`/test-feature` step 3 now splits the unreachable-target branch the way the CLI does.** It
   said "if it stays down … mark the cases FAIL, and stop" for both cases; `runTestFeature`
   instead exits 1 with the start command and no report when an app *it started* never answers,
   and runs the session anyway (producing FAIL cases and a report) when there is no start command
   for that host and port. The body now states both, and the test pins both sentences.

14. **`NATIVE_NOTES.tester` and step 4 now name the screenshot destination**
   (`test-reports/tmp/screenshots/<screen>-<viewport>.png`, matching
   `src/workflows/test-feature.ts`), so a native run does not drop PNGs outside the tester's
   sanctioned — and gitignored — write area, the way Playwright MCP's default output directory
   would. The designer's note already pinned its own path.

15. **The generated marker names the file a reader should actually edit.** Agent files keep
   `— edit agents/*.md instead`; command files say `— edit scripts/sync-claude.ts instead`, since
   the three command bodies are string constants in the generator. The matched prefix
   (`GENERATED by scripts/sync-claude.ts`) is unchanged, so `isGenerated`/`syncFile` still
   recognise every previously generated file.

16. **`/review` step 7 no longer points a target repo at `npx tsx src/cli.ts review`.** The file is
   copied into repos that have no `src/cli.ts`; it now names the toolkit CLI (`aw review`)
   instead. `/design-loop` step 7 likewise substitutes `$1` into the stop line rather than
   printing the literal `<feature>` placeholder, so the resume command is copy-pasteable — which
   is what deviation 8 above claimed.
